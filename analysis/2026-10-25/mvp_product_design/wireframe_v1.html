      7 - Runs & export

      A run stores its inputs, engine version, data version and results. Opening a saved run is read-only; editing creates a new draft.

      Saved runs

      RunScenarioPeriodStatusEngine / dataSaved (AWST)

      Run IDs, versions and times are placeholders. AWST (Australia/Perth) is UTC+8; the same clock time as Asia/Shanghai.

      Export

      • RReadable report (HTML) - English; scenario, assumptions with source tags, period labels, plan vs outcome, checks, limitations
      • Cschedule_30min.csv - power, SOC, reserves, meter, per interval
      • Callocation_30min.csv - energy and FCESS MW per interval
      • Cactivation_days.csv - per day: flag, call, reason, calls left
      • Cledger_by_party.csv - item x party, with unit and denominator
      • Cchecks.csv - every check and failing interval
      • Jinputs.json - every input with source tag and versions
      Exports carry the same labels as the screen: HISTORICAL REPLAY, period, scenario tag, and "illustrative" or "assumption" where applicable.

      Interaction states (design review only)

      Every result-bearing panel uses one of these states. Frontend: implement them as shared components. Try them on the product screens with the controls below.

      Inputs changed - results stale

      Any input change. Old results stay visible but greyed with a stale badge; exports and save are disabled until recompute or undo.

      Running

      1. ✓Validate inputs
      2. ✓Load 09:00 forecasts
      3. …Own battery plan
      4. Customer policy
      5. Ledger and checks

      Named steps, elapsed time, Cancel. Never a fake percentage.

      Infeasible

      A hard constraint cannot be met with these inputs (e.g. reserve leaves no energy for the event, or standby + event exceeds max control). Shows the binding constraint and the input to change. No result numbers shown.

      NO BUSINESS CASE

      Computation succeeded, constraints hold, but Zenith loses money or customers are worse off. A first-class result with reasons, not an error.

      Unsupported in this build

      The engine cannot compute this combination (e.g. own-battery baseline for a non-default size). The panel says so and shows no number. A saved result for another configuration is never substituted.

      ? Missing data

      Inputs not available at 09:00 are drawn as hatched gaps and listed in the availability table. Missing is never zero; totals that depend on them say "incomplete".

      Failed

      Engine error or timeout. Shows step, error ID and Retry. Previous results stay, marked stale.

      Saved run - read-only

      Opened from Runs. Inputs locked, banner on every screen, "Duplicate as new draft" to edit.

      OUTCOME vs PLAN

      Plan values (09:00, expected) and outcome values (replayed settlement) never share a column. Outcome is hidden until revealed.
